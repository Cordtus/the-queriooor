## 2026-10-24 — Explorer network selector, per-row hash copy, dev-docs adoption

- **Progress:** Explorer endpoint selection collapsed from separate RPC/REST
  preset dropdowns to one **Network** selector that sets both endpoints from the
  same chain's cosmos.directory aggregates (`rpc.` + `rest.cosmos.directory/<slug>`);
  curated preset lists removed. Every row in the RPC and LCD transaction result
  lists now has a **Copy** button for its hash that does not expand the card.
  Adopted Dev Docs Discipline (index, architecture, data model, integration,
  operations state, onboarding, audit record) and rewrote the root `AGENTS.md`

  pair so the two sides can never point at different networks. Manual edits stay
  possible and switch the selector to **Custom endpoints**. One-sided chains
  leave the missing endpoint empty instead of silently substituting another
  network. The explorer keeps its own parsing helpers rather than importing
  `src/` (single-file constraint); the duplication is recorded as a coupling.

  switching, REST-only chain handling, and custom-URL fallback checked.

## 2026-10-24 — Retry RPC queries through a different node when indexing is disabled

- **Progress:** Event Search now calls `searchTxs()`. When the RPC payload says
  `transaction indexing is disabled` (or `tx indexer is not enabled`), it loads
  the selected chain's entry from `https://chains.cosmos.directory/<chain>`
  (`best_apis.rpc`, else `apis.rpc`), picks a random credential-free HTTPS node
  that is neither the current host nor another cosmos.directory aggregate, and
  retries the same `/tx_search` once. The node that works is remembered for later
  pages of the same network so pagination stays on one index; changing the
  network clears it.
- **Decisions:** Only the missing-index payload triggers a retry; other HTTP and
  JSON errors are surfaced as before (HTTP status wins over a JSON error body).
  Candidate lists and the chosen node are in memory only; the endpoint fields are
  not rewritten. Custom endpoints with no resolvable chain slug are not retried.
- **Verification:** `yarn test` 41 pass, including the committed `searchTxs`
  retry tests (two requests, fallback success, preferred-node reuse, plain 502
  not retried, no-fallback indexing message), `pickAlternativeRpc`, and
  `isTxIndexDisabled`. A headless harness also exercised the same path in the
  browser.
- **Docs:** architecture hazard, integration registry row, data-model session
  state, and `docs/testing.md` updated.
- **Next:** release and record the deployment.

## 2026-10-27 — Ask the RPC aggregate for indexed nodes

- **Progress:** `/tx_search` requests to the cosmos.directory aggregate now carry
  `x-cosmos-require-index: 1`, so `rpc.cosmos.directory/<chain>` prefers nodes last
  recorded with a transaction index. `api/proxy.js` forwards that header only for
  the aggregate's `/tx_search` with the exact value `1`, advertises it in CORS,
  and `dev-server.js` now passes request headers through the shim. Copied curl
  commands include the header only for the aggregate.
- **Decisions:** use the aggregate's routing hint rather than polling
  `status.cosmos.directory/<chain>` (no new state or repeated status fetches).
  The payload-driven fallback retry stays as a safety net for stale/missing index
  status, direct/custom nodes, or an aggregate that ignores the hint.
- **Verification:** `yarn test` 43 pass, including proxy header-forwarding
  (aggregate only, value `1` only), CORS preflight, and `searchTxs` header
  assertions. Spot-checked six consecutive header-bearing live requests, all
  returned results; earlier unheaded probes had produced intermittent
  `transaction indexing is disabled`.
- **Docs:** architecture hazard, integration upstream/proxy contract,
  `docs/testing.md`, `README.md`, and the deploy verification command.
- **Next:** release and record the deployment.
